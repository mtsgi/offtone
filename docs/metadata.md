# 音楽タグと画像キャッシュ

## パーサーの選定

| 比較項目            | music-metadata 12.3.3                                                                            | jsmediatags 3.9.7                                            |
| ------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| MP3 / M4A / FLAC    | ID3v2、MP4、Vorbis Comment / PICTURE に対応                                                      | 3 形式に対応                                                 |
| 型                  | TypeScript の型を同梱                                                                            | 別途型定義が必要                                             |
| ブラウザー / Worker | `parseBlob` は Web API の Blob を使用。Worker で実測                                             | ブラウザー対応。Worker での利用は今回未検証                  |
| サイズ              | npm 展開時約 756 KB。今回の Worker ビルドは約 284 KB、gzip 約 85 KB                              | npm 展開時約 236 KB。実際の Worker バンドルは未計測          |
| 読み込み            | Blob tokenizer はランダムアクセスでき、duration 計算を無効にすれば音声データ全体を読む必要がない | File reader による部分読み込みに対応。形式ごとの実測は未実施 |
| 画像                | `common.picture` に MIME とデータを取得できる                                                    | picture タグを取得できる                                     |

`music-metadata` は型、Blob API、メモリー割当上限を備え、3 形式の検証を同じ API で行えるため採用した。ブラウザー向け export を Vite で解決し、Worker 内で `parseBlob` のみを使う。[music-metadata](https://github.com/Borewit/music-metadata) / [jsmediatags](https://github.com/aadsm/jsmediatags)

## 動作と制限

フォルダー走査後に一覧を表示し、File を単一 Worker に順次渡す。メインスレッドで音声全体を ArrayBuffer にしない。リクエスト ID、世代番号、Worker の停止、書き込みトランザクションの abort で古い処理を排除する。曲ごとの表示情報を個別に更新し、解析結果を受け取るたびにライブラリやキュー全体を再構築しない。再生中の曲だけ Media Session を更新する。Worker を利用できない場合はファイル名で表示し、再生を継続する。30 秒で応答しない Worker は停止し、次の曲へ進む。キャンセル後は再開可能。

既存の v2 `tracks` レコードに縮小画像 Blob を追加するため、スキーマ変更はない。ルート ID と相対パスで識別し、サイズ・更新日時・解析バージョンが一致すればキャッシュを使う。曲が削除されればそのルートの古いレコードを整理する。音声の原本は保存しない。DB の読み書き失敗時も再生と表示は継続し、保存できない旨を表示する。

画像は JPEG、PNG、WebP に対応し、パーサーの単一割当と画像入力を 4 MiB に制限する。Worker の `createImageBitmap` / `OffscreenCanvas` で最大 256 ピクセルに縮小し、128 KiB 以下のみ保存する。API 非対応や不正画像ではプレースホルダーを表示する。デコード後に 1600 万画素を超える画像は破棄するが、デコード前に画素数を確実に制限できないため、悪意ある圧縮画像の一時的なメモリー消費は完全には防げない。巨大なタグは解析失敗となりファイル名にフォールバックする。Blob URL は置換、削除、フォルダー切替、ストア破棄時に解放する。

## 検証

`src/__tests__/fixtures/` の自作 CC0 音源を使い、Node の Blob 解析で 3 形式のタイトル・アーティスト・アルバム、MP3 の JPEG を検証した。Chromium の実際のモジュール Worker 上でも同じ 3 ファイルのタグと MP3 の画像縮小を確認した。テストはキャッシュヒット・ファイルとバージョンの変更・キャンセルと再試行・Worker エラー・保存失敗・画像制限・再生中の Media Session 更新も検証する。

Android 実機での大きなライブラリ、巨大・破損画像のピークメモリー、フォルダー切替、キャンセル、バックグラウンド再生とロック画面は未検証。実際の M4A / FLAC 埋め込み画像、画像デコード失敗のブラウザー実測、ブラウザーのファイル選択から IndexedDB までの通し操作は追加確認が必要。
